# 仓库功能图

仓根的 `repo-map/features.json` 手写，随每次改动按 `xy-workflow` 更新，只写功能、目的、理由出处、目录、根功能子仓和外部依赖。归属、行数、关系、标记与页面从 Git 跟踪文件推导；外部依赖由根登记，使用者从代码和文档识别。

画图、更新图或看图都走 `xy-cleanup` 的功能审批（把变化的功能做成卡片交用户定留不留），不只出图；随改动改清单不算更新图。首次出图没有认可记录，所有功能均视为变化。

首次创建 `repo-map/features.json` 时一并创建 `repo-map/skip.json`，按 `xy-cleanup` 决定页询问一次。文件必须保留；无路径写 `[]`。

## 功能清单

功能对象必须且只可有以下通用字段：

| 字段 | 用途 |
|---|---|
| `id` | 全树唯一的稳定标识；小写字母开头，只含小写字母、数字和连字符。 |
| `title` | 给人看的功能名，非空。 |
| `what` | 一句话说明要什么，让他一眼认出是哪个东西、要它做成什么；只说要点，细节留给子功能和条目，不写现在分几条路径、几个阶段、几个模块；非空。 |
| `why` | 功能为什么需要，以及理由出处。 |
| `directory` | 仓内相对目录；仓库根写 `""`。 |
| `items` | 用户层面的功能条目数组；没有条目时写 `[]`。 |
| `children` | 子功能数组。 |

`what` 和条目文字给仓库主人看：他认得自己敲的命令、改的配置、看的页面和报表，不认得代码里和本 skill 里的叫法。照当面讲给他听的说法写：用他叫得出的名字，说谁做什么、看得到什么结果；一句只说一件事，放不下就拆成条目。已有的文字只在用了自造的词、名词串，或代码里、本 skill 里的叫法时才改；先指出是哪个词，指不出就不动。

根功能的 `directory` 须为 `""`。每个非根功能的 `directory` 须为安全、唯一的仓内相对路径：非空、不以 `/` 开头或结尾、不含 `\\`，无空段、`.`、`..`；目录内须含至少一个 Git 跟踪文件，并嵌套在上级功能目录中。从子功能目录向上最近的功能目录须正好是它的上级；普通目录可以隔在两者之间。

每个 `items` 对象只含 `id`、`text`、`status`。条目 id 在本功能内唯一，格式同功能 id，引用写 `功能 id:条目 id`。text 是一行非空文字，只写一件可验证、可单独取舍的用户结果或约束，不写实现、参数或文件名，用户平时敲的命令除外；能说「做了一半」就拆开，总是一起留删则合并。两原则冲突时，以能单独取舍为准。status 仅为 `确认` 或 `起草`：AI 新写或改写的条目标 `起草`，显示「等你拍板」；用户确认这条文字后才改为 `确认`。

根功能必须有 `subrepositories` 字段，记录另有功能图的独立子仓目录；无时写 `[]`。它是仓内相对目录路径数组：非空、不以 `/` 开头或结尾、不含 `\`，不得有空段、`.` 或 `..` 段。重复路径按集合比较，不报错。子功能不能有该字段。

根功能必须有 `external_dependencies`，登记仓外依赖名，无时写 `[]`。名字非空、首尾无空白且不含换行；重复不报错。子功能不得有此字段。

`used_by_repositories` 可选，登记用到本仓的其他仓（相对本仓根的路径），清扫判没人用时往上反查这些仓；`[]` 表示用户定了不查别的仓，没有这个字段表示还没定。

`why` 必须且只含 `text`、`source`、`quote`、`from` 四个字段：

| `source` | `quote` | `from` |
|---|---|---|
| `原话` | 用户说过的话或用户规范的逐字原文，非空。 | 原话或规范的明确来历。 |
| `确认` | 空字符串。 | 用户确认回答的来历。若引用 `answers.json`，写成 `<路径>/answers.json#answers.<键>`，多个键用英文逗号隔开；回答编号按 JSON 键读取。 |
| `起草` | 空字符串。 | 空字符串。 |

回答编号写作 `answers.<键>`，因为 GitHub 链接中的 `#L7` 会被理解为第 7 行；`check` 只检查引用格式，不读取回答文件。

`why` 必须含非空 `text`；`check` 只查格式，不核实引文。新增或修改清单时，审查者逐条核对 `from` 所指原件。`起草` 表示理由未确认，页面标为「等你拍板」。

最小清单：

```json
{
  "id": "sample",
  "title": "示例仓库",
  "what": "说明仓库提供什么。",
  "why": {
    "text": "需要一个可校验的功能清单。",
    "source": "起草",
    "quote": "",
    "from": ""
  },
  "directory": "",
  "items": [],
  "subrepositories": [],
  "external_dependencies": [],
  "children": []
}
```

清单约束：

外部依赖名须在 Git 跟踪代码或文档中整词出现，且不得与仓内目录名同名。
gitlink 与未忽略目录内的嵌套 Git 仓均报「还不支持子仓」。被忽略规则直接点名的嵌套仓须登记在根 `subrepositories`，遗漏时报错并列路径。登记路径若当前存在却不是被忽略规则直接点名的嵌套仓也报错；路径缺失则可接受。合格子仓不入图；被忽略目录不再向下查找，以避开工作树和依赖缓存。
符号链接归「其他」且不跟随。读取候选代码、测试或文档时，以原始字节识别 NUL；命中后归「其他」，不解码、不计数、不推导关系。其余普通文本若有已知但不支持统计的代码后缀，检查时报错并列路径。

## 跳过名单

`repo-map/skip.json` 是必需的仓内相对路径数组；每项须为 Git 跟踪文件，或以 `/` 结尾且含跟踪文件的目录。路径非空、不以 `/` 开头、不含 `\\`，无空段、`.`、`..` 和重复项。`check`、`render`、`render-workspace` 都校验。

名单单独存 `skip.json`，明确记录不参与统计和清扫的路径。文件必须显式存在；无路径时仍写 `[]`。

命中跟踪文件归「其他」，零行且不从中推导 `import`、外部依赖或路径提及。未跳过文件指向跳过路径时，入站关系仍保留。清扫不逐行覆盖、查重复块或生成改稿。

## 文件、行数与依赖

只处理 `git ls-files` 返回的文件；每个文件恰好归一个功能。

| 分类 | 判定与计数 |
|---|---|
| 测试 | 代码后缀的文件位于 `tests`、`test`、`benches`、`test_data`、`testdata`、`fixtures` 目录中，或文件名为 `test_*.py`、`*_test.py`、`*_test.rs`、`*_tests.rs`、`tests.rs`、`conftest.py`；所有非空行都计为测试。 |
| 代码 | 已支持的代码后缀，以及 `.html`；依照语言规则区分代码、文档字符串与注释。HTML 中完全位于 `<!-- -->` 注释里的行计为注释。 |
| 文档 | `.md`、`.rst`，且不在测试目录中；所有非空行都计为文档。 |
| 其他 | 符号链接、含 NUL 字节的文件、`repo-map/skip.json` 列出的路径，以及其余非代码、非文档文件，行数为零。 |

`doc_chars` 统计 `lines.docs` 中的非空白字符，包括 Markdown 非空行及代码文档字符串、文档注释；不计代码、测试、普通注释和其他文件。

归「其他」路径不读。读取代码、测试或文档时不跟随符号链接；扫描原始字节发现 NUL 后不再解码该文件。其余内容按 UTF-8 解码，无效字节以替代字符继续计数和推导关系。Git 跟踪文件读取失败则报错并指出路径。

`repo_map_lib/constants.py` 维护代码后缀；已知但未支持统计的后缀会使检查失败并列出文件。

检查器按文件路径所在的最深功能目录计算物理归属；审查者核对该目录是否符合文件实际服务的功能，以及测试断言实际检查的行为。导入和提及只产生使用关系，不代替这项语义核对。

## 目录怎么摆

检查器只核目录结构；下面的放法按语义由审查判断。

1. 文件按服务对象放：代码和文档放进它所实现的功能的目录，别的功能用到它不改归属；测试归它断言检查的功能，只当驱动、夹具或依赖用到的功能不算。服务几个功能、不专属其中一个的（共用设施、把子功能接起来的入口与分发、讲整组的文档、验证几个功能合起来行为的测试）放进它们最近的共同上级。一份文件混着几个功能各自的内容，能按代码本身的约束拆开就拆开，拆不开的按第 2 条归能容纳它的最近一层。
2. 代码本身的约束优先：语言的包与 crate 根、模块私有性、仓库自己的依赖规矩（如分层、导入边界）定了文件只能放在哪时，照约束放，放不进服务对象目录的归能容纳它的最近一层功能；条目跟着实现走，登记在实现它的文件所在的功能下。另一种语言的部分在那层自成模块时，可在那层下单列子功能。各仓自己的依赖规矩写在各仓，不写进本 skill。
3. 不设没有自己文件的子功能：只靠上级文件实现的行为是上级的条目。
4. 挪动文件时同步改路径、导入、调用方、文档和部署命令，不留旧路径兼容。
5. 新功能和它的目录、代码在同一次改动里登记；还没做的功能不进图。

Python `import` 用 AST 解析，仅用于显示代码之间的 `import` 关系；模块名仅在仓内唯一匹配 `.py` 代码文件时成立，相对导入按当前文件目录解析，测试文件中的导入也建关系。`import` 和提及都不改变文件归属。

代码和文档中的路径或目录名提及生成 `mention`。路径须含 `/`，匹配处两侧不能紧邻字母、数字、下划线、点、连字符或斜杠；路径关系连到路径所指文件的主人。目录名只匹配有直属文件的功能，且匹配处两侧不能紧邻字母、数字、下划线、连字符或斜杠；写在路径里的目录名由路径匹配处理。外部依赖名按整词边界匹配，由根功能声明并按文件直接归属统计，不向上汇总。来源功能若是目标功能目录的祖先，不建关系，因为上级介绍下级是在说明组成。提及只显示关系，不改归属。同一功能对已有 `import` 时不另记 `mention`；仅非祖先或子孙关系显示相互依赖。

## 推导结果

`map-data.json` 顶层恰有 `root`、`features`；`features` 以功能 id 为键，包含：

- `title`、`directory_name`、`parent`、`children`、`what`、`why`、`items`。根功能的 `directory_name` 取 `git worktree list --porcelain -z` 中主检出的目录名，因此从 linked worktree 出图也显示仓库名。
- `lines.own` 是直属行数，`lines.total` 是含所有子功能的行数；两者都分代码、文档、注释、测试。
- `doc_chars.own` 和 `doc_chars.total` 分别是直属及含所有子功能的文档非空白字符数。
- `files` 是直属文件的排序路径数组。
- `uses` 列出所用功能及关系类型 `import` 或 `mention`。
- `external_uses` 列出代码和文档推导的外部依赖名，排序、去重；无时为 `[]`。
- `markers` 只列「等你拍板」。

理由来源为「起草」或存在起草条目的功能带「等你拍板」标记；两者同时起草只标记一次。

## 命令

参数都须显式提供，且 `--repo` 必须是仓根绝对路径。参数错误退出 `2`，清单或仓库检查错误退出 `1`，通过（含标记）退出 `0`。

```sh
python3 <xy-repo-map目录>/repo_map.py check \
  --repo <仓根绝对路径>

python3 <xy-repo-map目录>/repo_map.py render \
  --repo <仓根绝对路径> \
  --out <不存在或为空的输出目录>

python3 <xy-repo-map目录>/repo_map.py render-workspace \
  --repo <主仓根绝对路径> \
  --out <不存在或为空的输出目录>

python3 <xy-repo-map目录>/repo_map.py publish \
  --out <render 输出目录> \
  --as <当前|清扫前|清扫后>
```

`check` 校验清单、子仓、支持后缀、文件归属、行数、依赖和标记。

`render` 完成同样校验后读取 `repo_map_lib/render_feature_tree/templates/feature-tree.html`，嵌入数据并写 `index.html` 与 `map-data.json`；模板放在负责出图的功能目录内。输出目录必须不存在或为空。页面是可离线打开、适配手机的单页功能图，默认显示图视图，也可切到文字视图。图视图是根在中间、分支分到左右两侧的横向树，只画指向子功能的箭头，不画功能间引用；圆越大表示行数越多（含子功能），同色表示总图中的同一个仓或单仓图中的同一个顶层分支。点节点弹出与文字视图相同的详情小窗。图可放大、缩小：打开时按可读大小显示、以根为中心，图比屏幕宽时可横向滑动，「全图」缩到整张可见。页头显示根功能名、「要什么」「为什么」及出处；点击根名看详情，树从其子功能开始。详情列出条目并标记起草项。功能行与详情的「用到」都列仓外依赖并标「外部」，且不可点击；节点还显示哪些功能使用它。文字视图默认展开根下两层；行数条按占父功能比例缩放并分代码、测试、文档、注释。筛选「等你拍板」仅作用于文字视图，只显示带标记功能及各级上级，隐藏其他功能；直属内容摘要仍按当前展开状态显示。零行功能仍显示 `0 行`。页内数据与 `map-data.json` 相同，但不含 `files`。

`render-workspace` 分别用 `build_map` 校验主仓和每个登记子仓；主仓至少登记一个，子仓须已检出、是 Git 仓根且有有效 `repo-map/features.json`。失败退出 `1` 并说明子仓及原因；缺清单时提示先起草只有根功能的清单，未检出时提示到其目录运行；参数错误退出 `2`。组合保留主仓根，按登记顺序把子仓根接在子功能后；子仓 ID 加路径前缀，并同步改写 `parent`、`children`、`uses` 和 `files` 数组中的路径前缀。子仓指标不变；不递归合并子仓登记的其他仓。

各子仓根的 `lines.total` 和 `doc_chars.total` 计入主仓根。外部依赖只在声明仓以外匹配目录名；主仓根目录名取主检出名，子仓根取登记路径末段，其他目录功能取目录末段。唯一匹配时把名称从 `external_uses` 移入目标功能 `uses`，关系为 `mention`；目标已有 `import` 时优先保留。源目标互为祖先或子孙时只移出外部依赖，不加关系；无匹配或多匹配仍显示为不可点击的外部依赖。「用到」按钮和详情显示完整功能名（标题、目录名）。`check`、`render` 仍只处理本仓图；`publish` 不变。

`publish` 只接受同时含可读、非空 UTF-8 `index.html` 和 `map-data.json` 的目录；站点名由 `map-data.json` 生成，不接受手写。单仓固定名为根 `directory_name` 加 `-map`；功能 ID 含 `/` 的组合图加 `-overview-map`。`--as 当前` 覆盖固定站点；`--as 清扫前`、`--as 清扫后` 追加发布当天本地日期与 `-before`、`-after`，保留快照。无法读取页面或 map-data、缺根功能或缺 `directory_name` 时，参数检查以 `2` 退出。把命令输出链接交给用户。
