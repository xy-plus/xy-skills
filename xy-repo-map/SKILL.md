# 仓库功能图

`repo-map/features.json` 是仓库根目录下的人维护清单，只写功能、目的、理由出处、入口、根功能的独立子仓登记和外部依赖名字；外部依赖名由根功能声明，使用者从代码和文档推导。文件归属、行数、依赖、标记和页面均由 Git 跟踪文件推导。

用户画图、更新图或看图，都走 `xy-cleanup`：画图后清扫变过的功能并找可删项，不能只交图；日常顺带维护清单不算更新图。首次画图没有认可记录，所有功能都算变过。

首次创建 `repo-map/features.json` 时一并创建 `repo-map/skip.json`，按 `xy-cleanup` 的决定页面问用户一次。此文件必须保留；没有跳过路径时写 `[]`。

## 功能清单

功能对象必须且只可有以下通用字段：

| 字段 | 用途 |
|---|---|
| `id` | 全树唯一的稳定标识；小写字母开头，只含小写字母、数字和连字符。 |
| `title` | 给人看的功能名，非空。 |
| `what` | 一句话说明要什么：写用户要的结果和约束，不写现在分几条路径、几个阶段、几个模块；非空。 |
| `why` | 功能为什么需要，以及理由出处。 |
| `directory` | 对应目录的仓内相对路径；仓库根写 `""`；不对应目录写 `null`。 |
| `entries` | 仓内相对文件路径，或以 `/` 结尾的目录路径；目录入口包含其下所有跟踪文件。 |
| `children` | 子功能数组。 |

根功能必须有 `subrepositories` 字段，记录另有功能图的独立子仓目录；无时写 `[]`。它是仓内相对目录路径数组：非空、不以 `/` 开头或结尾、不含 `\`，不得有空段、`.` 或 `..` 段。重复路径按集合比较，不报错。子功能不能有该字段。

根功能必须有 `external_dependencies` 字段，列出仓外依赖名；无时写 `[]`。名字须为非空字符串，首尾无空白且不含换行；重复不报错。子功能不能有该字段。

`why` 必须且只含 `text`、`source`、`quote`、`from` 四个字段：

| `source` | `quote` | `from` |
|---|---|---|
| `原话` | 用户说过的话或用户规范的逐字原文，非空。 | 原话或规范的明确来历。 |
| `确认` | 空字符串。 | 用户确认回答的来历。 |
| `起草` | 空字符串。 | 空字符串。 |

`text` 须非空。`check` 只校验格式，不判引文是否为用户原话；新增或改动清单时，审查者须逐条核对 `from` 指向的原件。`起草` 表示用户尚未确认，页面会显眼标「等你拍板」。

最小清单：

```json
{
  "id": "sample",
  "title": "示例仓库",
  "what": "说明仓库提供什么。",
  "why": {
    "text": "需要一个可校验的功能清单。",
    "source": "起草",
    "quote": "",
    "from": ""
  },
  "directory": "",
  "subrepositories": [],
  "external_dependencies": [],
  "entries": [],
  "children": []
}
```

清单约束：

根功能的 `directory` 须为 `""`；每个功能的 id 唯一。
`directory` 非空时，其下须有 Git 跟踪文件；目录只能对应一个功能，子目录功能须位于最近的祖先目录功能内。
每条 `entries` 路径须存在并位于该功能最近的目录功能内，且不能位于另一目录功能内；目录入口须以 `/` 结尾。
无子功能的目录功能须用 `entries: []`；目录本身已登记其全部跟踪文件。
每个外部依赖名须在至少一份 Git 跟踪的代码或文档中被整词提及，且不能与仓内目录功能的目录名相同。
gitlink 和未忽略目录内的嵌套 Git 仓仍报「还不支持子仓」。被忽略规则直接点名的嵌套 Git 仓须登记在根功能的 `subrepositories`；漏登记时报错并列出路径。登记路径若在当前检出存在、却不是被忽略规则直接点名的嵌套 Git 仓，也报错；不存在则不报错。合格的登记子仓不进入功能图。被忽略目录不再向内查找，因为那里通常是工作树和依赖缓存。
符号链接、含 NUL 字节或路径上已归为「其他」的文件均先归「其他」；其余普通文本文件若使用已知但暂不支持统计的代码后缀，检查报错并列出文件。

## 跳过名单

每仓必须有 `repo-map/skip.json`（仓内相对路径数组）；无跳过路径时写 `[]`。每项是 Git 跟踪文件，或以 `/` 结尾且下面至少有一个跟踪文件的目录。路径须非空、不以 `/` 开头、不含 `\\`，不得有空段、`.` 段、`..` 段或重复项。`check`、`render`、`render-workspace` 均校验此文件。

名单独放在 `skip.json`，不并入 `features.json`：旧版功能清单校验器不接受新增字段，也不会读取独立文件，仓库可先提交名单，再由新版校验。此文件必须显式存在，不能将缺失当空名单，否则漏建会让应跳过内容悄悄进入统计和清扫；无跳过路径时也写 `[]`。

命中的跟踪文件归「其他」，行数为零、不读内容，也不据此推导 import、外部依赖或路径提及。其他文件导入或提及它，关系仍照 `vendor` 文件生成；文件归属仍由功能清单决定。清扫不逐行覆盖、不扫描重复块、不生成改写稿；命中的 `TODO.md` 不进入 `todo_items` 审查。

## 文件、行数与依赖

只处理 `git ls-files` 返回的文件；每个文件恰好归一个功能。

| 分类 | 判定与计数 |
|---|---|
| 测试 | 代码后缀的文件位于 `tests`、`test`、`benches`、`test_data`、`testdata`、`fixtures` 目录中，或文件名为 `test_*.py`、`*_test.py`、`*_test.rs`、`*_tests.rs`、`tests.rs`、`conftest.py`；所有非空行都计为测试。 |
| 代码 | 已支持的代码后缀，以及 `.html`；依照语言规则区分代码、文档字符串与注释。HTML 中完全位于 `<!-- -->` 注释里的行计为注释。 |
| 文档 | `.md`、`.rst`，且不在测试目录中；所有非空行都计为文档。 |
| 其他 | 符号链接、含 NUL 字节的文件、`repo-map/skip.json` 列出的路径，以及其余文件（包括 `third_party`、`vendor`、`node_modules` 下的文件），行数为零。 |

`doc_chars` 是 `lines.docs` 各行的非空白字符数，包括 Markdown 非空行及代码中的文档字符串、文档注释行；代码、测试、普通注释和其他文件不计字数。

归为「其他」的路径不读内容。读取代码、测试或文档时不跟随符号链接；发现 NUL 字节即归「其他」。其余内容按 UTF-8 解码，无效字节以替换字符解码后照常计数并推导依赖。Git 跟踪文件读失败时，检查报错并指出路径。

`repo_map_lib/constants.py` 维护代码后缀。已知但不支持统计的语言后缀会使检查失败并列出文件。

文件归属顺序：

1. 文件归所在的最深目录功能。
2. 无子功能的目录功能直接拥有文件。
3. 有子功能时，显式列在 `entries` 的文件归登记它的功能；祖先和子孙同时登记时，以子孙为准。
4. 其余非测试文件从入口沿 Python `import` 向下查找，仅在同一目录功能内；遇到无亲缘关系的功能入口即停止。
5. 多个功能共同登记或查找到同一文件时，归最近共同上级并标「共用」。
6. 未归属文件归目录功能并标「整体」。目录功能有这类代码或测试时，显示「没归到功能的代码或测试」。
7. 未登记测试先看它直接导入且与测试文件同属一目录功能的代码。文件名对应仅适用于 `test_*.py`、`*_test.py`、`*_test.rs`、`*_tests.rs`，且只在当前候选中查找；`tests.rs` 不对应。同目录功能无导入代码时，再看它导入的其他目录功能中的代码，并归代码所属功能。涉及多个功能时归最近共同上级并标「共用」；仓内代码一处都未被导入时，才归测试所在目录功能并标「整体」。

Python `import` 用 AST 解析；模块名仅在仓内恰好匹配一个 `.py` 文件时成立，相对导入按当前文件目录解析。测试代码的 import 仅用于判定测试归属。

代码和文档中的路径提及、其他目录功能名提及会生成 `mention` 关系。路径提及须带 `/`，匹配处两侧不能紧邻字母、数字、下划线、点、连字符或斜杠；目录名按整词匹配。外部依赖名也按目录名整词边界匹配；名字在根功能声明，使用者只按文件直接归属判断，不向上汇总。来源文件所属目录功能若是目标所属目录功能的祖先，无论路径还是目录名提及都不生成关系；上级介绍文件提及下级是在说明组成。提及只供页面显示，不改文件归属。同一功能对同时有 `import` 和 `mention` 时保留 `import`。只有互非祖先或子孙的功能才显示相互依赖。

## 推导结果

`map-data.json` 顶层恰有 `root`、`features`、`markers`；`features` 以功能 id 为键，包含：

- `title`、`directory_name`、`parent`、`children`、`what`、`why`。根功能的 `directory_name` 取 `git worktree list --porcelain -z` 中主检出的目录名，因此从 linked worktree 出图也显示仓库名。
- `lines.own` 是直属行数，`lines.total` 是含所有子功能的行数；两者都分代码、文档、注释、测试。
- `doc_chars.own` 和 `doc_chars.total` 分别是直属及含所有子功能的文档非空白字符数。
- `files.registered`、`files.reached`、`files.directory`、`files.shared`、`files.whole` 按归属原因列出直属文件。
- `uses` 列出所用功能及关系类型 `import` 或 `mention`。
- `external_uses` 列出代码和文档推导的外部依赖名，排序、去重；无时为 `[]`。
- `markers` 列出「等你拍板」「还没实现」「没归到功能的代码或测试」。

`markers` 汇总三种标记的数量。无目录、无子功能、无入口的功能标「还没实现」；目录功能有子功能，且代码或测试文件的行数落在「整体」时，标「没归到功能的代码或测试」。功能粒度细于文件时可以没有行数，页面显示「—」。

## 命令

参数都须显式提供；`--repo` 须为仓根绝对路径。参数错误退出码为 `2`；功能清单或仓库检查错误退出码为 `1`；检查通过（即使有标记）退出码为 `0`。

```sh
python3 <xy-repo-map目录>/repo_map.py check \
  --repo <仓根绝对路径>

python3 <xy-repo-map目录>/repo_map.py render \
  --repo <仓根绝对路径> \
  --out <不存在或为空的输出目录>

python3 <xy-repo-map目录>/repo_map.py render-workspace \
  --repo <主仓根绝对路径> \
  --out <不存在或为空的输出目录>

python3 <xy-repo-map目录>/repo_map.py publish \
  --out <render 输出目录> \
  --as <当前|清扫前|清扫后>
```

`check` 校验清单、子仓、支持后缀、文件归属、行数、依赖和标记。

`render` 完成同样校验后读取 `repo_map_lib/templates/feature-tree.html`，嵌入数据并写 `index.html` 和 `map-data.json`；模板路径须列在「出图」功能的 `entries` 中。输出目录必须不存在或为空。页面为可离线打开的单页，只画手机友好的功能树，不显示实现文件。页头显示根功能名、「要什么」「为什么」及其出处；点击根功能名打开详情，树从根功能的子功能开始。功能行和详情面板的「用到」都列出外部依赖并标「外部」，外部依赖使用不可点击的元素。默认显示根下两层。行数条长度表示占父功能的比例，条内按代码、测试、文档、注释分段。筛选「等你拍板」时，只显示带标记的功能及其各级上级，不显示其他功能或「没细分到子功能的部分」。页面内嵌数据与 `map-data.json` 相同，但不含 `files`。

`render-workspace` 用 `build_map` 分别检查主仓和每个登记子仓。主仓至少登记一个子仓；每个子仓须在当前检出中，是 Git 仓根且有有效 `repo-map/features.json`。检查失败退出 `1`，错误指出子仓及原因；缺清单时提示先起草只有根功能的清单；子仓不在当前检出时提示到其检出目录运行。参数错误退出 `2`。组合时主仓根不变，按登记顺序将子仓根接在其子功能末尾；子仓功能 id 加登记路径前缀，并同步改写 `parent`、`children`、`uses` 和 `files` 中的路径。子仓自身行数和标记不变；主仓根的 `lines.total` 和顶层标记计数累加各子仓。不会递归组合子仓登记的其他仓。

各子仓根的 `lines.total` 和 `doc_chars.total` 加入主仓根。外部依赖名只在声明该名字的仓以外查找目录名恰好匹配的功能。主仓根目录名取主检出名；子仓根取登记路径末段，其他目录功能取目录末段。唯一匹配时，名字从 `external_uses` 移入指向该功能的 `uses`，关系为 `mention`；同目标已有 `import` 时保留 `import`。源和目标互为祖先或子孙时，仅移出外部依赖，不加关系。无匹配或多匹配时，继续显示为不可点击的外部依赖。功能行「用到」按钮和详情面板均显示完整功能名（标题和目录名）。`check` 和 `render` 仍只检查或生成当前仓自己的图；`publish` 不变。

`publish` 要求目录同时含 `index.html` 和 `map-data.json`；站点名从 `map-data.json` 生成，不接受手写。单仓固定站点名为根功能 `directory_name` 加 `-map`；功能 id 含 `/` 时，组合图固定名加 `-overview-map`。`--as 当前` 每次覆盖固定站点；`--as 清扫前`、`--as 清扫后` 分别追加发布当天本地日期和 `-before`、`-after`，保留清扫快照。map-data 无法读取、缺少根功能或根功能无 `directory_name` 时，参数检查失败并退出 `2`。把命令输出的链接交给用户。
