# xy-goal

跨会话的长目标会被执行者自己的毛病拖垮，xy-goal 只管这五件事：

| 毛病 | 机制 |
|---|---|
| 转述时把要求滤掉或放宽 | 用户原话逐字落盘、编号，作为权威 |
| 事项和要求对不上 | 每个事项通过出处挂到原话 |
| 换会话后忘了要求 | 契约落盘，新会话接管同一份文件 |
| 在办的事没人推 | 每个开放事项都有下次核时间，定时自查 |
| 自己判自己做完 | 产物由 xy-review 审查者审，机械判据凭命令和退出码 |

## 契约

一份契约三个文件，同在 `~/.claude/xy-goal/`、同名：清单 `<YYYYMMDD-HHMMSS>-<slug>.md`、原话 `<同名>.quotes.md`、账本 `<同名>.done.md`。一个会话一份契约，几个主题的事项都登记在里面。`session` 写本会话 claude 的进程号（Bash 里 `echo $PPID`），`cron_job_id` 写定时器编号。

清单只放在办 `[ ]` 和做完待验收 `[x]` 的事项，每项四行：

```markdown
# <目标>
session: <echo $PPID>
cron_job_id: <CronCreate 返回值>

## 清单
- [ ] T1 <一句话标题>
  - 判据：<怎么算做完，可核实>
  - 出处：原话 <N>、<M>
  - 产物：在跑：<名字>（pid <进程号>）；下次核：<本机时间 YYYY-MM-DD HH:MM>；<持久指针；还差什么>
- [ ] T2 <一句话标题>
  - 判据：…
  - 出处：原话 <N>
  - 产物：等：T1；下次核：…
- [x] T3 <一句话标题>
  - 判据：…
  - 出处：原话 <N>
  - 产物：待验收：<产物指针>；下次核：…
```

字数线是用户要求的：每项四行合计不超过 300 字，清单文件全文不超过 5000 字，原话和账本不计；超了就压短条目，不调线。

判据只许两类：产物类，由 xy-review 审查者审；机械类，文件在不在、命令退出码，由执行者跑命令。写不成这两类的，改判据，或改成 `等：用户：…` 由用户的下一条原话收口。判据只写完成条件；出处至少一个原话编号，用户改口时补进新编号；自己提出的新要求先问用户。

产物栏第一段写谁在动：`在跑：<名字>（pid <进程号>）`，只写一个推进者，本会话自己推进就写本会话的进程号；或 `等：<T 号，多个用「、」>` 或 `等：用户：<待定的事>`；`[x]` 写 `待验收：<产物指针>`。第二段一律是 `下次核：YYYY-MM-DD HH:MM`，本机时间，不超过 12 小时；过点后下次自查先核真实状态再改时间。等待目标必须是同一份清单里的开放事项，`[x]` 可以是等待链的终点，等待链不能成环。指针要能活到验收；设计、过程和证据记在仓库或报告，不塞进契约。

验收通过或用户明确取消后，立即从清单移出并写入账本，一行一项：

```markdown
- T1 <一句话>（<产物指针>；验收 <审查结论，或命令和退出码>）
- [~] T2 <一句话>（原话 <N>：「<取消摘句>」）
```

取消必须有原话依据；未完成事项不得删除，放宽判据也必须有原话依据。

## 原话怎么记

每条用户消息逐字照抄进原话文件，一条消息一段，按顺序从 1 编号，不重排、不删；用户消息里的空行照抄。标注只认顶格；用户消息里顶格的「（原话」缩进一格，这是唯一允许对正文做的改动。每段开头一行标注落点：

```markdown
（原话 1 → T1）<用户消息原文>

（原话 2 → T1；规矩：CLAUDE.md；无：提问已答）<用户消息原文>
```

落点三类：事项 `T1`（多个用「、」）、通用规矩 `规矩：<写入的位置>`、不带可跟踪要求的内容 `无：<原因>`；一段多类用「；」隔开。通用规矩当场写进持久位置再标。用户新来的话先照抄并标好落点，再分析和行动。原话是权威，判据是它的索引：判据可以按最新原话改措辞，原话本身只增不减。

## 定时自查

`CronCreate(cron="*/15 * * * *", recurring=true, prompt=<下方整段>)`，契约路径写清单文件的绝对路径；创建后回填 `cron_job_id`，`CronList` 核对只有这一个：

```text
本次契约：<清单绝对路径>
python3 ~/.claude/skills/xy-goal/check.py ~/.claude/xy-goal，报的问题按报告改，但不改原话正文。
逐项核实产物当前真实状态：看文件、跑命令，不靠记忆；能推进的当场推进。
把 `[x]` 送验；新冒出的工作追加到清单。
新要求先逐字记入原话文件并标落点。
```

换会话继续同一份契约：旧会话还开着就先在旧会话 `CronDelete`；新会话把清单的 `session` 改成自己的进程号，`CronCreate` 新定时器并回填 `cron_job_id`，`CronList` 核对只有这一个。定时器 7 天过期，过期后也这样重建。`check.py` 只认清单里写的 `session`，一个 `session` 一份契约。

## 验收与关闭

产物类事项送 xy-review 审查者审，它从文件读原话和产物，结论「通过」或「改了就过且已改完」就是验收；机械类事项由执行者跑命令，账本记命令和退出码。驳回的事项退回清单，把可复核的理由写进产物栏。

关闭只有一条路：剩余事项全部验收或取消；再回溯本会话里说过稍后做、顺手发现未记录、用户中途改口的事项，补入清单并验；`CronDelete(id=<cron_job_id>)` 确认成功后汇报逐项状态和验收证据；然后删掉三个文件。
