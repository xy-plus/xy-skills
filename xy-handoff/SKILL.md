## 归属与拆分

- 会话里第一件动手做的事是本会话唯一的大任务；TaskCreate 只放它的小任务，不加父子层级。
- 每条新用户消息，先判归属，再做别的（包括加载其他 skill）：修正、补充、追问、改口、验收当前大任务的，留在本会话；有独立完成标准、当前大任务不做它也能验收的，是新大任务。当场能答、不用调查、不留产物的提问就地答，不算大任务。
- 新大任务直接交出去，回复「不要」，事后告知；只有归属两边都说得通、拿不准时，先问用户一句。一条消息有几件大任务：属于当前大任务的留下；还没有大任务时留第一件；其余各自交出去。
- 当前大任务一个会话做不完、能分成几件分别验收的：先定共用接口、格式及每件完成标准，再把几件交出去，回复「要」；本会话留下拆分、集成和整体验收。能在一个会话里从设计做到验收完，就不再拆。只是本大任务里一段有界的活、做完交回结果的，才用子代理。
- 同时交出去的几件互不依赖；有先后的，等前一件交付再交后一件。
- 交出去的会话归它自己：原会话不停它、不删它，收尾时它也不算原会话建过的东西；回复「不要」的，原会话也不等它、不再跟进。

## 交出去

按 `xy-runs` 放 `handoff.md`，以下字段写全：

- 派你的会话：名字、短 id。
- 你接的事：哪一件、做到什么算完；原话里其余的事归谁。接手会话只做分给自己的这一件。
- 回复：「要：完成后向派你的会话汇报，它在等」或「不要：直接向用户汇报」。
- 收尾方式：用户明确要求交给后台代理的写「完成后保留」，其余写「完成后删除本会话」。
- 用户原话：逐字，附原件位置。
- 这件事特有的规矩：全局说明自动加载，不抄；没有就写「无」。
- 已核实的事实。
- 要你自己定的事。
- 边界：不碰的东西；派你的会话已定、不能自行改的共用接口和格式，要改先问它。

目录取这件事所在仓库的主检出根目录；与仓库无关就用原会话的启动目录。启动前用 `claude agents --json` 查现有名字；`-n` 必填，用说清这件事、不与现有会话重名的中文短名，名字也是 SendMessage 的收件地址。用子 shell，原会话自己的工作目录不变：

```bash
(cd "<目录>" && claude --bg -n "<中文名>" "请先读交接说明 <路径>，然后照做。这件事由你全权负责，结论按交接说明里的回复方式汇报。")
```

从启动输出 `backgrounded · <短 id> · <名字>` 记下实际名字和短 id，用 `claude agents --json` 按该短 id 核对它在跑，不按预想名字查。核对和告知都以启动输出为准；每个会话按此格式各填一行：

```text
<会话名>（<短 id>）｜claude attach <短 id>｜回复：<要/不要>｜收尾：<完成后删除本会话/完成后保留>
```

## 等回复、补话与返工

本会话交出去、回复「要」的，每件在任务清单记一项，写会话名、短 id；结束本轮，说明在等哪几件，不用盯着或轮询，对方做完会发消息。收到汇报逐件验收，不合格发回原接手会话。仅当本大任务所有回复「要」的交付均已验收通过，才开始集成和整体验收，再按本会话自己的回复和收尾方式收尾；未齐就结束本轮继续等。

补话或返工都发回原接手会话，原会话自己不做；转用户的话要逐字加原件位置。用 `claude agents --json --all` 按短 id 查：还在且进程在，就用 SendMessage 发；进程已停，先 `claude respawn <短 id>` 再发；已删除，带原上下文拉回后再用 SendMessage 发，不新开交接：

```bash
(cd "<它的启动目录>" && claude --bg --resume <完整会话 id>)
```

## 接手与收尾

有问题，谁知道问谁：觉得派你的会话知道，就用 SendMessage 问它；觉得只有用户知道，就问用户。按用户回答做，包括用户改掉派方已定的接口和格式，不等派方确认；回答大幅改变预期、可能影响派你的会话的决定，就顺便用 SendMessage 告诉它，一般的回答不用。

失败、卡住、在等用户、有未提交或未推送的改动、`claude rm` 拒删：保留并照实汇报，不加强删参数。交接说明也不能豁免这些保留条件。

大任务已完成并验收、没有等用户回答的事、本任务收尾已做完（交出去的会话不算），先照常写最终汇报，再按「回复」二选一：

- 「要」：用 `claude agents --json --all` 查派你的会话，进程已停的先 `claude respawn <它的短 id>`；用 SendMessage 发一行结论、交付在哪、`claude --resume <自己的完整会话 id>`。派你的会话已不在列表里或消息发不过去，改用 PushNotification 告诉用户，本会话保留。
- 「不要」：用 PushNotification 给用户发一行：会话名、一行结论、`claude --resume <自己的完整会话 id>`。

收尾为「完成后保留」的，汇报后保留。收尾为「完成后删除本会话」的，汇报送达后才能删除；回复「不要」且通知明确因用户正在看本会话而未发出时，也可删除。其余汇报失败就保留。删除是最后一个动作：

```bash
claude rm "$(basename "$CLAUDE_JOB_DIR")"
```
