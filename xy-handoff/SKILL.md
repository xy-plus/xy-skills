## 归属与拆分

- 会话里第一件动手做的事是本会话唯一的大任务；TaskCreate 只放它的小任务，不加父子层级。
- 每条新用户消息，先判归属，再做别的（包括加载其他 skill）：修正、补充、追问、改口、验收当前大任务的，留在本会话；有独立完成标准、当前大任务不做它也能验收的，是新大任务。当场能答、不用调查、不留产物的提问就地答，不算大任务。
- 独立新任务若需要自己的编排者来派子代理、合入或和用户来回商量，就交给另一个会话，回复「不要」，事后告知。若一个子代理就能做完、不需要另设编排者，就开子代理做；本会话收到结果后交付用户，这不算本会话的大任务。只有归属两边都说得通、拿不准时，先问用户。一条消息有几件大任务时，当前大任务的事留在本会话；还没有大任务时留第一件；其他独立任务逐件按上述规则处理。
- 当前大任务拆出适合独立验收的实现件时，由本会话定共用接口、格式和完成标准，再编排并派子代理；本会话负责拆分、审查与需要本会话作出的判断、集成和整体验收。这些实现件仍属当前大任务，不交给另一个会话编排。不适合再拆就不拆。流程明确要求另开会话的任务（如 xy-goal 清扫）仍交出去，并回复「要」。
- 按职责交出去时，先查已有会话；职责匹配的就按补话方式交给它，并说明做完是否要回本会话。没有匹配会话时，再新开会话交接。
- 同时交出去的几件互不依赖；有先后的，等前一件交付再交后一件。
- 交出去的会话归它自己：原会话不停止或删除它；收尾时它也不算原会话创建的东西。回复「不要」的，原会话不等它、不再跟进。

## 交出去

交接说明由派方写，接手方只读，不修改。按 `xy-runs` 放 `handoff.json`，`kind` 必填，只能是「普通」或「清扫」：

普通交接：

```json
{"kind": "普通",
 "from": {"name": "派你的会话名", "short_id": "短 id"},
 "task": {"what": "接哪一件", "done_when": "做到什么算完", "others": "原话里其余的事归谁"},
 "reply": "要",
 "quotes": [{"text": "逐字原话", "source": "原件路径"}],
 "rules": "这件事特有的规矩，没有写 无",
 "facts": ["已核实的事实"],
 "decide_yourself": ["要你自己定的事"],
 "boundaries": ["不碰的东西"]}
```

清扫交接只用于 xy-goal 的 T1 清扫，只有以下五个字段：

```json
{"kind": "清扫",
 "from": {"name": "派你的会话名", "short_id": "短 id"},
 "reply": "要",
 "contract": "派方契约目录的绝对路径",
 "changed": [{"path": "改过的文件的绝对路径", "in_use_by": "还有谁在用，没有写 无"}]}
```

普通交接的 `reply` 写「要」（子任务，汇报派方）或「不要」（独立任务，自己交付用户并保留）；清扫交接的 `reply` 只能写「要」。接手会话只做分给自己的这一件；接手任务也按「归属与拆分」中的同一规则判断是否继续拆分。普通交接的 `rules` 不抄自动加载的全局说明；`boundaries` 还须写明派方已定的共用接口和格式，要改先问它。

普通交接的 `quotes` 至少一条，其余数组可为 `[]`。清扫交接的 `changed` 至少一项，按 xy-goal「清扫」一节列出；`path` 是本机绝对路径，别的机器上的文件写「用户@主机:/绝对路径」；`in_use_by` 写还在使用该文件的会话或人，没人用写「无」。`contract` 必须是已有契约目录的绝对路径，目录下的 `quotes/` 至少有一个内容（去掉空白后）非空的 `<N>.md` 原话文件。

接手方见到 `kind` 为「清扫」的交接，就按 xy-review 的清扫审查规则处理：从 `changed` 列出的路径起审，用户原话从 `contract` 下的 `quotes/` 读取。

下文 `<本 skill 目录>` 是这份 SKILL.md 所在的目录：用 Skill 工具加载时就是 Claude Code 给出的 Base directory，经 CLAUDE.md 引入时就是引入路径所在的目录。派方写完自己运行 `python3 <本 skill 目录>/check_handoff.py <路径>`，按报错改到退出 0 才启动接手会话。

目录取这件事所在仓库的主检出根目录；与仓库无关就用原会话的启动目录。启动前用 `claude agents --json` 查现有名字；`-n` 必填，取一个说清这件事的短名，尽量用中文，不与现有会话重名，名字也是 SendMessage 的收件地址。用子 shell，原会话自己的工作目录不变：

```bash
(cd "<目录>" && claude --bg -n "<名字>" "请先读交接说明 <路径>，然后照做。这件事由你全权负责，结论按交接说明里的回复方式汇报。")
```

从启动输出 `backgrounded · <短 id> · <名字>` 记下实际名字和短 id，用 `claude agents --json` 按该短 id 核对它在跑，不按预想名字查；刚起就失败、没接手的，用 `claude rm <短 id>` 删掉，改对了再起。核对和告知都以启动输出为准；每个会话按此格式各填一行：

```text
<会话名>（<短 id>）｜claude attach <短 id>｜回复：<要（子任务）/不要（独立任务）>
```

## 等回复、补话与返工

本会话每件回复「要」的交接任务都记入任务清单，写会话名和短 id。结束本轮时说明正在等哪些任务；不盯着或轮询，等对方发消息。是否完成以收到消息为准，不能凭产出文件判断，因为文件可能不是最终版。消息到达后逐件验收。

清扫任务验收前，派方对接手方最后一轮的 `review-razor.json` 跑同仓 `xy-review/check.py`，要退出 0，且报告的 `cleanup_handoff` 是本会话写的那份清扫交接说明路径；还须确认「要用户定」的事都已取得答复（接手方问的是用户还是本会话，由它定）。没问或没答复就不验收、不允许自删；发回去要求先询问，也不代用户作答。其他任务不要求中途问用户。未通过的发回原接手会话；通过后按补话方式回复「验收通过，可以自删」，对方已删除则不用回复。

等本大任务除 xy-goal 清扫外的所有「要」交接任务都验收通过后，再做它们之间的集成（包括需等前置任务就绪的界面接入、端到端）和整体验收。xy-goal 清扫与关闭前复核并行，不阻塞这段集成和整体验收；整体验收通过后，仍按 xy-goal 等 T1 清扫验收通过，再按本会话自己的回复方式收尾。未全部通过就结束本轮并继续等。

补话或返工都发回原接手会话，原会话自己不做；转用户的话要逐字加原件位置。用 `claude agents --json --all` 按短 id 查：还在且进程在，就用 SendMessage 发；进程已停，先 `claude respawn <短 id>` 再发；已删除，带原上下文拉回后再用 SendMessage 发，不新开交接：

```bash
(cd "<它的启动目录>" && claude --bg --resume <完整会话 id>)
```

## 接手与收尾

有问题，谁知道问谁：觉得派你的会话知道，就用 SendMessage 问它；觉得只有用户知道，就问用户。按用户回答做，包括用户改掉派方已定的接口和格式，不等派方确认；回答大幅改变预期、可能影响派你的会话的决定，就顺便用 SendMessage 告诉它，一般的回答不用。

失败、卡住、在等用户、有未提交或未推送的改动、`claude rm` 拒删：保留并照实汇报，不加强删参数。交接说明也不能豁免这些保留条件。

大任务已完成并验收、没有等用户回答的事、本任务收尾已做完（交出去的会话不算），先照常写最终汇报；向用户发出的汇报或通知（含 PushNotification）最后一句写「本会话可以关闭」；向派方汇报不用写。再按「回复」二选一：

- 「要」（子任务）：用 `claude agents --json --all` 查派你的会话，进程已停的先 `claude respawn <它的短 id>`；向仍在的派方用 SendMessage 发一行结论、交付在哪、`claude --resume <自己的完整会话 id>`。未送达时复查同一列表，用 PushNotification 如实通知用户：确认不在列表才说「之前负责交付的会话已不在」；仍在则说「派方仍在但消息未送达」及失败原因；查不清就说状态未知。通知附一行结论、交付在哪、自己的恢复命令，保留本会话，不自删。送达后也保留本会话，结束本轮，说明在等派方验收，不用盯着或轮询；收到派你的会话发来的「验收通过，可以自删」，最后自删。
- 「不要」（独立任务）：用 PushNotification 给用户发一行：会话名、一行结论、`claude --resume <自己的完整会话 id>`；保留本会话。

自删：先停掉本会话还在跑的后台任务（`run_in_background` 的命令、Monitor），还有在跑的，`claude rm` 只会停掉本会话、登记还在；再执行 `claude rm "$(basename "$CLAUDE_JOB_DIR")"`。用户让本会话关掉或关闭自己，也是汇报后自删；`claude stop` 只停进程、会话仍留在列表里，不算关掉。
