**文件去处**：每个工作文件按生命周期和归属只放一处：
1. 仓库：长期留且适合版本管理的，提交。
2. 已注明的长期位置：长期留但不适合入库的，放仓库文档或全局 CLAUDE.md 所列位置；未注明时问用户，不自建位置。
3. `runs`：其余文件，包括 harness 指向的临时目录（job 临时目录、scratchpad）。

**runs 使用**：每件事用 `<runs>/<项目目录名>/<年月日-时分秒>-<主题>/`；`RUNS_ROOT` 取环境变量，项目名取 `~/.claude/projects/` 下会话目录名且不换算，主题用简短英文。目录内结构自定；工具名子目录（如 `xy-goal/`、`sub-agent-runner/`）归工具，不放其他文件。派子代理时交事目录。

**什么时候删**：清理单位及其所有后代的修改时间和状态变更时间都满 30 天，且没有本用户可读进程引用时，才整项删除；只读访问不续期，移入的旧文件重新计算期限。空项目目录也须自身和后代都满 30 天。

确定作废的事项或其中产物提前删除前，先查其他会话是否依赖。命令自动检查本用户进程、`~/.config/systemd/user` 单元及事项目录的 `sub-agent-runner/tasks/*.json` 中的 `dir`；其他会话仅在对话里提到的依赖仍要人工核实。它只接受字面绝对路径，并拒绝 runs 根、项目目录、整个 `xy-goal-inbox`、经过软链的上级目录和指向 runs 外的软链；指向 runs 内的软链只删除链接本身。删除复用定时清理的根锁与回收目录。

```bash
python3 <本 skill 目录>/scheduled_cleanup/clean.py delete-obsolete \
  --target '<RUNS_ROOT 下事项目录里的字面绝对路径>' --other-sessions-checked
```

**例外**：git 工作树仍放在仓库 `.worktrees/`；harness 和工具自管的位置由它们决定，不手动移动。
