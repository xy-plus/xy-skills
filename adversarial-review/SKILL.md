# 对抗审查

审查者的任务是找出问题，不是确认没问题。尺子是用户原话，不是 spec 或计划。

## 给审查者的说明（照抄，填尖括号）

```markdown
审查对象：<文件路径或提交范围>
用户原话：<原话编号及所在文件，审查者自己去读>
对照：<最简的现成做法，例如老实现的文件和行号；没有写「无」>

逐条查，每条都要回复：
1. 第一性原理：拿用户原话逐条对照，做的不多也不少；多做的列出来（用户同意才留），少做的列出来；改的是出错的地方本身，不是在别处加东西收拾后果。
2. 难误用：原话要的用法一步就能做对，用错当场报错。
3. 奥卡姆剃刀：列出所有能删的东西（功能、参数、分支、测试、文档句子）和删了丢什么；留下的每样都说得出离了它原话哪条过不了；比对照大出的部分逐段说明为什么必需；碰到的旧代码里能删的也列出来。
4. 仓库规范：逐条查。

结果照 adversarial-review 的「结果格式」写到 <报告路径>，最后一条回复只写四节结论和删除清单条数。
```

## 结果格式

```markdown
## 第一性原理
查了：是
多做：<逐条，或「无」>
少做：<逐条，或「无」>
补丁：<逐条，或「无」>
结论：通过 | 不通过

## 难误用
查了：是
问题：<逐条，或「无」>
结论：通过 | 不通过

## 奥卡姆剃刀
查了：是
删除清单：<逐条：删什么、删了丢什么；或「无」加理由>
旧代码删减：<碰到的旧代码里能删的，逐条，或「无」>
结论：通过 | 不通过

## 仓库规范
查了：是
问题：<逐条，或「无」>
结论：通过 | 不通过
```

字段值可以写在冒号后，也可以接着写多行列表；写「无」也必须写出来。

## 收到结果后

1. `python3 ~/.claude/skills/adversarial-review/check.py <报告路径>`：缺节、缺「查了：是」、缺字段、字段为空、结论不是「通过」或「不通过」，都报错并退出 1，此时把报告退回重审。
2. 删除清单逐条照删，除非能说出离了它原话哪条过不了。
3. 多做的问用户，少做的补上。
4. 旧代码删减另开以删为目的的任务：功能不变（闸全绿、冻结结果逐位一致），代码变少。
